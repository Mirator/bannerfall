## Why this matters and current state

The audit found saves generated by normal play that are rejected on reload, settlements permanently blocked by orphaned occupation, invisible storage errors, and additional battle/harness errors. Existing tests pass because they do not cover these transitions. Bannerfall is a static native-module canvas game with no production build or runtime dependencies. Preserve its instance-method phase seams, RNG domains, fixed-step tests, schema boundaries, and performance budgets. Read AGENTS.md and tests/README.md before editing.

1. `src/world.js` decrements positive `waryT`/`clashT` using `-= dt`; `persistParties` stores negative values through `|| 0`. `src/save.js` rejects them and the repository deletes rejected saves. Ordinary 25/6-second timers become about -1/60. Saturate timers and narrowly recover previously emitted expired negatives through an explicit documented migration/normalization, without accepting arbitrary malformed values or changing unrelated fields.
2. `src/world/settlement-interactions.js`'s final-camp absorption removes fitting stronghold-homed parties regardless of `occupying`. Preserve deployed occupiers (and inbound raiders) during remnant absorption so their settlement lifecycle remains coherent; roaming remnants may still reinforce within the current ceiling.
3. `Game.reportSaveFailure` assigns `saveWarning`, but no renderer reads it. Draw a persistent, legible warning across relevant scenes and avoid “campaign saved” assurances while a campaign write is unresolved/failed. Recovery must clear a warning only when the relevant failed operation is actually recovered, not merely after an unrelated settings write. Test visible output, not just a property.
4. `World.updateRegionalPressure` only checks the last-free-site guard for neutral targets. Apply it across all available unclaimed sites before preferring player-held targets. Cover three occupied sites plus one owned free site, and inbound reservations.
5. Bootstrap awaits all storage reads and only logs on rejection. Show a visible, recoverable startup error state without treating unreadable campaign data as absent, deleting it, or overwriting it. Prefer an explicit retry UI over silently entering an unsaved campaign. Handle each slot read failure and repeated retry without duplicate runtime loops/listeners.
6. `src/battle/terrain.js:placeCamp` draws shared plank/collider x/y from `fxRng`. Move physical placement to the supplied gameplay terrain RNG; keep decorative sizes in FX. Assert physical geometry is independent of FX seed. Seeded layout may legitimately change; review actual/expected/diff images, preserve budgets, and use the Visual baselines workflow if recapture is needed.
7. Intro accepts orders, but `_deployOrdered` is only written during deploy, so explicit FOLLOW becomes HOLD on confirmation. Remember explicit pre-fight choices during intro and deploy; preserve untouched default FOLLOW-to-HOLD promotion, ambush behavior, and existing command seams.
8. The campaign harness's `claim` returns on refusal; `nextUnclaimed` selects the same nearest refused site again. Track destinations attempted separately from ownership for each planned route stage. ClaimRush must visit each destination once; mixed policy may retry earlier refusals in a later stage deliberately, but must not repeat within the same stage. Record/assert visits, preserve deterministic records, and remeasure the sweep without weakening acceptance guards.
9. Reinforcement arrivals increase `totalEnemies`, but loot reads initial `setup.enemies` only. Count types actually deployed, including arrived waves, without paying unarrived waves or double-paying. Keep lootFor as the one reward formula and preserve initial setup semantics.
